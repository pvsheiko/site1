# Подключение Supabase и Telegram

## 1. База
Создайте проект Supabase в своем аккаунте. Откройте SQL Editor → New query, вставьте весь `leads.sql`, нажмите Run. Скрипт создает `leads`, RLS, функции сохранения и блокировки уведомлений. Публичных политик доступа нет; anon и authenticated не имеют доступа. SQL рассчитан на новую таблицу проекта. Если таблица leads уже существует с другими полями, не удаляйте данные: сначала согласуйте миграцию.

Project URL: Settings → Data API. Серверный ключ: Settings → API Keys → Secret key (`sb_secret_…`); старый `service_role` тоже подходит. Публичный publishable/anon ключ для этой формы не нужен.

## 2. Бот
Telegram → @BotFather → /newbot → имя и username, заканчивающийся на bot. Сохраните токен безопасно. Откройте своего бота → Start и отправьте ему сообщение. Для студии рекомендуется отдельный бот: у бота может быть только один webhook.

## 3. Vercel
В проекте сайта → Settings → Environment Variables добавьте только для нужного окружения:
- `SUPABASE_URL` — Project URL.
- `SUPABASE_SECRET_KEY` — серверный секретный ключ. Отметить как Sensitive.
- `TELEGRAM_BOT_TOKEN` — токен BotFather. Отметить как Sensitive.
- `TELEGRAM_WEBHOOK_SECRET` — отдельная случайная строка из менеджера паролей, 32–256 символов A–Z, a–z, 0–9, _ или -. Отметить как Sensitive. Это НЕ токен бота.
- `SITE_URL` — реальный HTTPS-адрес опубликованного сайта.

Ни у одного ключа не должно быть префикса NEXT_PUBLIC_. Сделайте Redeploy после изменения переменных. Настройки Vercel и настройки облачной среды Codex — разные места; значения не передаются между ними автоматически.

## 4. Узнать чат без передачи токена в чат/адресную строку
Откройте на собственном HTTPS-сайте `/bot-setup`. Введите значение TELEGRAM_WEBHOOK_SECRET из менеджера паролей → «Найти chat_id». Страница обращается к серверу; токен бота в браузер не передается. Сообщения пользователей не выводятся, только числовые ID. Никому не передавайте этот секрет.

Добавьте полученный `TELEGRAM_CHAT_ID` в Vercel. Для личного чата его достаточно. Для группы также задайте `TELEGRAM_ADMIN_USER_ID` равным ID человека, которому разрешено управлять заявками. Сделайте Redeploy. Чужой пользователь/чат не сможет просматривать заявки или менять статусы.

Если webhook уже установлен, поиск chat_id через getUpdates не работает. Используйте ранее известный ID или свой личный ID от @userinfobot; в личном чате они совпадают. Настройка не удаляет существующий webhook автоматически.

## 5. Подключить команды
Снова откройте `/bot-setup`, введите секрет подключения → «Подключить бота». Дождитесь подтверждения. Бот будет использовать `/api/telegram`, webhook защищен заголовком Telegram и проверкой chat/user ID.

В боте:
- `/leads` — последние 5 заявок;
- `/new` — последние 5 новых заявок;
- `/help` — помощь;
- кнопки «В работу» и «Завершена» — меняют статус в Supabase.

Страница подключения не сохраняет введенный секрет в localStorage. Закройте страницу после настройки. Не присылайте секреты в переписке, не открывайте URL с токеном бота в браузере.

Альтернатива для разработчика: из `site/`, с переменными в игнорируемом `.env.local`, `npm run telegram:chat-id` и `npm run telegram:webhook`. Скрипт не печатает токен или секрет.

## 6. Проверка перед запуском
Проверьте политику обработки данных `/privacy`: это технический черновик на известных фактах. До публичного сбора заявок уточните юридические сведения оператора, контакт, сроки хранения и условия передачи/обработки данных с учетом выбранных сервисов и региона. Не указаны вымышленные реквизиты или гарантии.

Отправьте форму с пометкой «ТЕСТ» → убедитесь, что запись появилась в Table Editor → leads и сообщение дошло в Telegram → нажмите «В работу», затем «Завершена» → проверьте status в таблице. Удалите тестовую строку при необходимости. Проверьте, что посторонний аккаунт не получает заявки.

## Поведение при ошибках
Успех показывается, только когда заявка сохранена в Supabase или доставлена владельцу в Telegram. Если Telegram недоступен, запись остается в базе; автоматического фонового повторения уведомления пока нет. Восстановленную заявку можно найти через /leads или /new. Если Supabase недоступен, Telegram получает заявку без кнопок (статус нечего сохранять). Если недоступны оба сервиса — посетитель видит ошибку и ссылку Instagram.

Повтор запроса с тем же ID не создает новую строку в базе. При подтвержденной доставке повторное уведомление не отправляется. В редком случае, когда Telegram принял сообщение, а ответ потерялся, повтор может дублировать уведомление. Лимит: 3 заявки за 10 минут на HMAC сетевого адреса в базе; при сбое базы — дополнительный лимит в памяти экземпляра (не глобальный для всех Vercel-инстансов). Для усиления защиты при реальном спаме можно добавить Vercel Firewall/Turnstile отдельно.

Автономный HTML/PDF — статичные снимки старого дизайна, серверные заявки в них не работают. Для формы нужен развернутый Next.js-проект.

## Проверено в облачной среде
`npm test`, `npm run lint`, `npm run build`. Тесты используют только имитации API. Реальная SQL-схема, проект Supabase, отправка сообщений и webhook требуют ваших настроек и отдельного сквозного теста; без него подключение не считается завершенным.
